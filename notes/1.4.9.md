## Open-H3 Regenerate 2K: NVIDIA's open upscaler, in the upscale pass 🔍

NVlabs released an open version of MiniMax's H3-Regenerate-2K: your 768P draft gets upscaled in latent space, then re-rendered at 2560x1440 in only 3 steps. They ship it for their own Python pipeline, not for ComfyUI, so I wired it in.

**New node: Glide H3 LoRA (Diffusers)**
Their LoRA is saved with Diffusers names. ComfyUI's normal LoRA loader doesn't know those names for H3, so it loads it and does nothing, without any error. This node maps it properly onto ComfyUI's model (q/k/v and the feed-forward halves land on the right slices of the fused layers). It also takes the optional "Sharp curve" file, which only fits curve-form checkpoints like the Comfy-Org pruned ones. On other models it skips it and says so in the console.

Their file is three LoRAs merged into one, so the node gives each its own slider:
- **refiner**: the part that rebuilds detail at the new size
- **turbo**: LightX2V, what makes 3 steps enough (lower it and you'll need more steps)
- **sharp**: LMS Sharp, edges and texture (also scales the Sharp curve file)

1.0 everywhere is NVlabs' recipe, but the example workflow ships with **sharp at 0**: LMS Sharp is aggressive and can make skin texture and eyes worse in some shots, and turning it off loses no detail. With sharp at 0 you don't even need the curve file. `strength` stays on top as a master that multiplies all three, so workflows you already saved load exactly as before. The console prints the mix it actually used.

**New example workflow: Minimax_h3_Studio_Regenerate_2K.json**
Same as the upscale-only workflow, with their exact recipe:
- their LoRA instead of the 8-step one (it already contains LightX2V Turbo and LMS Sharp, so don't stack those on top)
- Euler, CFG 1, sigmas 0.909 > 0.857 > 0.667 > 0 (ManualSigmas)
- latent upscaler set to 3.69 MP = 2560x1440 (2.07 for 1080p)
- the sound comes from your draft, untouched, so lip sync stays exactly as rendered

**Files** (put them in `models/loras`), from [Efficient-Large-Model/Open-H3-Regenerate-2K](https://huggingface.co/Efficient-Large-Model/Open-H3-Regenerate-2K/tree/main/lora):
- `open_h3_regenerate_2k_lora.safetensors` (12.4 GB)
- `sharp_curve_branches.safetensors` (1.2 GB, optional: only if you turn sharp back up)

**Careful:** NVlabs made it for 5 second clips on a B200. A 15 second clip at 2K is about 3.5x the tokens of the 768P draft, so it's heavy. Try 1080p or a short clip first. The node keeps the LoRA in bf16 in RAM (about 6 GB), the file itself is FP32.

**Upscale mode is impossible to miss now** ⚠️
When "upscale pass" is ticked, the H3 STUDIO title in the mode bar turns into an animated hazard banner: drifting warning stripes, glowing triangles, WARNING! flickering to UPSCALE MODE. Forgetting that box on is how you end up re-rendering old latents in a draft workflow, so now you can't miss it.

**Takes: pick which render of a clip gets upscaled** 🎞️
Right-click a clip in the strip. Under the colours there's now a **Takes** list with every render of that clip, newest first: resolution, latent (full / tail / none) and time. Click one and it becomes the clip's draft. The latent band, the upscale pass and latent hold all use it.
- Handy when you draft the same clip at several canvas sizes: a quick 540p and a 768P, say. The newest one isn't always the one you want to upscale.
- A take you pick stays picked. H3 Studio won't swap it for a newer render on disk, until you render that clip again.
- Upscales of the clip are listed too, greyed out, so you can't pick one as a draft. That includes older upscale passes: tail only and bigger than the canvas.
- Same reading as the band: **full** is a whole pink tag, **tail** is the word in pink with a small chunk at the end.
- Hover a take for its file name. The clip's tooltip says "picked by hand" when it's a pinned take.

**Draft and upscale workflows now share the project's renders**
Each workflow keeps its own copy of the project inside its H3 Studio node. So a clip rendered in the draft workflow was only recorded there, and the upscale workflow kept pointing at the previous take, for the latent band AND for the upscale pass itself. Now every recorded render is also shared in the browser, and any H3 Studio showing that project picks up the newer one when you switch to it. The console says "render picked up from another workflow". And if a clip's record is behind what's on disk (a project file saved before the render, or a render made before this update), H3 Studio now finds the newest DRAFT of that clip by itself. Drafts and upscales share the same file names, so it tells them apart by the size of the saved latent: only a canvas-sized one counts as a draft.

**Upscale to: a real target size for the upscale pass** 🎯
I was testing the chunked upscaler nodes (MMH3 Ultimate Upscale, for low VRAM), wired H3 Studio's width and height into its size, and got my 544p draft back. Same size, just re-rendered. In upscale mode the node reads the size from the saved .h3full, and it was sending that draft size straight out on width / height. So the upscaler did exactly what it was told. Nothing.
- Now the Canvas card has an **UPSCALE TO** dropdown (in orange): Off, 720p, 900p, 1080p, 1440p, 4K, Custom. The presets follow your ratio, so 16:9 gives 1920x1088 for 1080p.
- In an upscale pass, width / height go out at that size. Drafts still go out at the normal canvas, so nothing changes there.
- Off falls back to draft x refine multiplier.
- The canvas "all clips" button now copies the upscale size too, so you set it once for the whole film.
- The console says what it did: `960x544 -> 1920x1088 (upscale to)`.

**Refine multiplier: 2x by default, and you can see what it does**
- New clips start at **2x**. Old clips keep their own value.
- It's in the same orange as the positive_refine wire, so you can see it belongs to the second pass.
- Under it there's now a line with the actual reference sizes: `refs 576x896 -> refine 1152x1792`. Hover it for every image, source size, pass 1, refine. It's the same maths the node does, not a guess.
- One thing I didn't know until I looked: refine never goes past the picture's own pixels. So under **max**, a reference up to 2048px on the short edge is already full size, and the multiplier has nothing left to add. It says "capped at source" when that happens. Under **match** it does real work. And video references are never resized for the refine pass, only images.

**Takes list: shorter**
- Renders with no latent are hidden now. They can't be upscaled or held, and all my test runs made the list way too long. The current take always shows, whatever it is.
- The list tells you how many are hidden. Want them back: gear -> "Show takes without a latent".
- The mouse wheel scrolls the list now, instead of closing it. My bad on that one.

**New H3 STUDIO banner** 😎
The mode bar got the same treatment as the upscale banner, but calm: stripes, grain and glowing letters in the button blue (green in First / last), fading to black on both sides. Nothing moves. Upscale mode still gets the orange WARNING one, so you can't mix them up.
