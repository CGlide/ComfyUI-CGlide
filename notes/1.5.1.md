## Locking the doors

No new features in this one. The pack was still flagged on ComfyUI Manager, and the reviewer (thanks **ltdrdata**, for real) told me exactly why. So this release fixes all of it.

The short version: anyone who can reach your ComfyUI port can queue a graph with any widget values. There's no login on that. So a node that reads "any file you type" doesn't only read *your* files. It reads them for anyone. I was treating widgets as "the user's own graph, so it's fine". It's not fine. My bad.

**Files: only ComfyUI's own folders now** 🔒
Glide Vision, H3 Studio, Glide Join, Glide Upscale Hold, Glide DLSS5 and DLSS5 Batch only read from ComfyUI's **input**, **output** and **temp** folders, same rule as ComfyUI's own loaders.
- `..`, network paths (`\\server\share`, `//server/...`) and full paths outside those folders get refused, with a message that says why.
- Wiring H3 Studio's `source_video` into Glide Join and Upscale Hold works exactly like before. Those paths are already inside output.
- In Glide Join you can type a name like `MyProject/01_shot_00001.mp4`. It's looked up in output first, then input.
- Symlinks that lead out of those folders get refused too.

**Careful with this:** if you pointed Glide Join, DLSS5 or the DLSS5 batch folder at something like `D:\renders\...`, that stops working. Move the clips into ComfyUI's output folder (or link the folder in there) and use the name.

**DLSS5 output_directory: a folder inside output**
`output_directory` is now a folder name inside output. Type `Upscaled` and you get `output/Upscaled`. A full path is only accepted if it's already inside output. Empty works like before.
For the batch node: if your clips are in input or temp, the default result folder is now `output/DLSS5` instead of a folder next to the clips.

**Glide Vision: the server comes from your settings, not the node**
The vision server address used to come straight from the node's URL box. Now it has to match what you set on your machine. Out of the box that's a local Ollama, `http://localhost:11434`, so if that's your setup, nothing changes.
Anything else, set it before you start ComfyUI:
- LM Studio or another port: `set CSGLIDE_VISION_URL=http://localhost:1234`
- Ollama on another machine, or a cloud API: `set CSGLIDE_VISION_ALLOW_HOSTS=192.168.1.50` (or `api.openai.com`, etc.)

(`export` instead of `set` on Linux and Mac.) If the URL box doesn't match, the node tells you the exact line to set.

**Load from URL: no more DNS tricks**
Loading a picture from a link already blocked your own machine and your LAN. But the address was checked once and then looked up again on connect, so a sneaky DNS name could answer "public" the first time and "your router" the second. Now it connects to the exact address that passed the check. HTTPS still checks the certificate. Redirects and the Pinterest `og:image` link go through the same check.
One side effect: this loader doesn't go through a system HTTP proxy anymore. If you're on a network that only gets out through a proxy, Load from URL won't reach anything. Download the picture and drop it on the node instead.

That's it for this one. If something that worked for you in 1.5.0 is now refused and you think it shouldn't be, open an issue with the path or URL and I'll have a look. 👍
